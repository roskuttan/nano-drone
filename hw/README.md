# Nano drone hardware

The flight board is generated by code: schematic, placement, routing, planes, fab outputs and simulations all come
from the Python scripts here. Run them with KiCad 10's bundled Python
(`C:\Users\angel\AppData\Local\Programs\KiCad\10.0\bin\python.exe`).

| Step | Command (from `hw/`) | Output |
|---|---|---|
| 1. Schematic + ERC | `python design/nanodrone_sch.py`, then `kicad-cli sch erc kicad/nanodrone.kicad_sch` | `kicad/*.kicad_sch` |
| 2. Placement + outline | `python design/nanodrone_pcb.py` | `kicad/nanodrone.kicad_pcb` |
| 3. Rules, stackup, critical copper | `python design/nanodrone_route.py prep` | RF feed, driver power, fan-out, escape stubs, planes |
| 4. Routing | `python design/nanodrone_route.py grid` | grid maze router with rip-up and reroute (`tools/gridroute.py`) |
| 4b. Routing, hybrid (alternative to 4) | `python design/nanodrone_route.py route`, then `... repair` | Freerouting for the bulk (prep copper stays locked). `repair` runs DRC and lifts the autorouted copper into the grid router as rip-able routes. It then re-routes incomplete nets and every net in a violation (Freerouting cannot see the `.kicad_dru` EMC rules) with full rules, and prunes dangling copper |
| 5. Finish | `python design/nanodrone_route.py finish` | widen power/phase, pours, stitching/thermal/return vias, DRC |
| 6. Fab package | `python design/nanodrone_fab.py` | `output/fab/`: Gerbers + drill zip, JLC BOM/CPL, order notes, renders, STEP |
| 7. Post-layout simulations | `python sim_post/run_post.py`, then `python sim_post/report.py` | `sim_post/POST_LAYOUT_REPORT.md` |
| Pre-layout simulations | `python sim/run_all.py` | `sim/SIMULATION_REPORT.md` |
| 8. Enclosure | `python tools/board_ref.py <placed or routed board>`, then run the Fusion script `mech/fusion/nanodrone_enclosure` | `output/mech/enclosure/`: STL/STEP for the 3D-printed shells, fit checks, renders (`docs/ENCLOSURE.md`) |

All stages work on `kicad/nanodrone.kicad_pcb`. To work on a copy, set `NANODRONE_PCB` to another board path. For
KiCad's DRC to pick up the design rules, copy `kicad/nanodrone.kicad_pro` and `.kicad_dru` next to that board under
the same base name. `patch_project(pro, dru)` in `design/nanodrone_route.py` writes them for a variant's rules.

The finish stage (step 5) now also removes unused driver escape stubs (`trim_stubs`). It widens only the fixed
motor-current legs; the sense branches stay narrow. Its return-path stitching serves first the signal vias that move
between the L2 and L5 return planes.

### How the rev C board was routed

No single command reproduces the routed board. Steps 1-4 got to 102/110 nets. The rest came from a chain of
seeded repair runs on copies of the board (`NANODRONE_PCB=kicad/nanodrone_<x>.kicad_pcb`). Each run re-routes
only the nets it is told to rip:

1. `legs`: the 12 motor-current legs become fixed copper.
2. `eco_nfault`: removes the four nFAULT pull-ups (rev C, `NANODRONE_NFAULT_PU=0` in the schematic).
3. `repair`, with these settings:
   - 0.10 mm sense branches (`NANODRONE_PHASE_W`), 0.20 mm phase-to-analog spacing;
   - L4 open to digital, rail and analog nets;
   - negotiated congestion. This reached 108/110 (board N20).
4. Local finishing runs on the 0.0125 mm grid (`NANODRONE_GRID_RES`). Each one rips a few named nets
   (`NANODRONE_RIP`), routes them in a set order (`NANODRONE_ORDER`) and keeps the nets it must not touch
   (`NANODRONE_KEEP`). Weighted A* (`NANODRONE_ASTAR_W=1.2`) keeps them fast.
5. `eco_m4col`: moves motor 4's BEMF divider column 0.2 mm east (`M4_COL_X` in `design/nanodrone_pcb.py`), so
   ESC4's SWD pins get via sites.
6. Local finishing with phase sense branches allowed on L4. In order:
   - the rest of the SWD clock;
   - motor 1's phase A/B sense lines, which had blocked ESC1's SWCLK pin;
   - motor 4 phase A, after moving ESC4_SWDIO off its via site;
   - M4_DSHOT and M4_INLA, whose vias the column shift had come too close to.

   The result is `kicad/attempts/nanodrone_r1.kicad_pcb`: 110/110 nets. All intermediate boards are kept in
   `kicad/attempts/`.
7. The finish stage then found a floating B-pour island under U24. It held J2's antenna GND pad and the GND pads of
   motor 4's BEMF B/C dividers, so those dividers had no ground. No via fitted inside the island.
   - A GND via went in at (-3.76, -6.24), the one spot inside the island blocked only by a single net (M4_nSLEEP).
   - M4_nSLEEP was re-routed off L4. Analog and control nets re-routed through L4 there could split the VBAT plane
     feeding motor 4's driver.
   - Result: `kicad/nanodrone_z2.kicad_pcb`. DRC shows 0 violations and 0 unconnected items.

The finish stage now runs `stitch_islands`. It gives any GND pour island without a via its own via, or reports it.

Router lessons from that work (`tools/gridroute.py`):
- **Own copper:** counts as free only after eroding it by half a track plus the grid margin. Otherwise connections
  creep into a neighbour's clearance; this caused a real short.
- **Hard cells:** these and the board edge keep half a track. No-net pads keep 0.15 mm plus their mask opening.
- **Grid size:** 0.0125 mm wins about 10-20 % of channel capacity over 0.025 mm.
- **Multi-pin nets:** retry from another pin when the first one is boxed in, and defer clusters that fail.
- **KiCad rules:** the last matching custom rule wins, so the specific phase-to-analog rule comes last in
  `.kicad_dru`. `kicad-cli` needs `--all-track-errors` to report every error on a track.

Documents:
- `docs/ARCHITECTURE.md`: system architecture, pin maps, PCB, EMC and firmware notes.
- `docs/FIRMWARE_REQUIREMENTS.md`: what the Rust firmware must do because of the hardware.
- `docs/COST_ESTIMATE.md`: batch and per-drone cost.
- `docs/ENCLOSURE.md`: 3D-printed enclosure: design, mass and TWR, fit checks, printing and assembly.

Tools:
- `tools/kisch.py`: schematic-as-code.
- `tools/kifp.py`: custom footprints.
- `tools/kipcb.py`: placement helpers.
- `tools/gridroute.py`: router.
- `tools/render.py` and `tools/zoom.py`: PNG views.
- `tools/board_ref.py`: mechanical reference of the board (outline, holes, part boxes, motors) for the enclosure.
- `mech/enclosure_calcs.py`: hand calculations for the enclosure (duct sections, ring mode, struts, mass/TWR).
